# ADR-001: серверный Learning Engine

Статус: принят, 13 августа 2026.

## Контекст

Клиент `MaterialView` передавал серверу `page` и `totalPages`, а API вычислял завершённость по максимальному номеру страницы. Клиент мог объявить любое число страниц или сразу отправить последнюю страницу. Бизнес-правило было связано с HTTP, Prisma и React одновременно, поэтому его было трудно тестировать и переиспользовать.

## Решение

Первый модульный вертикальный срез находится в `src/modules/learning`:

- `domain` содержит события и чистую проекцию прогресса;
- `application` оркестрирует сценарий и зависит только от портов;
- `infrastructure` реализует порты через Prisma и политику доступа;
- `server` является composition root;
- Route Handler только аутентифицирует, валидирует DTO, вызывает сценарий и преобразует ошибки в HTTP;
- React отправляет наблюдаемые события, но не проценты и не общее число страниц.

Событие и текущая проекция сохраняются в одной транзакции. Для презентации процент считается по уникальным просмотренным страницам, а число страниц берётся из `CourseItem.totalSlides`. Общее событие завершения для презентаций отклоняется доменом.

## Правила зависимости

Допустимое направление:

`UI / HTTP -> server composition -> infrastructure -> application -> domain`

При этом `application` видит инфраструктуру только через свои порты, а `domain` не импортирует Next.js, Prisma и серверные библиотеки. ESLint закрепляет эти границы для новых модулей.

## Модель данных

`LearningEvent` — журнал фактов обучения. `CourseItemView` — быстрая проекция для интерфейса и отчётов. `viewedPagesJson` является переходным SQLite-представлением набора страниц; при переходе на PostgreSQL его следует заменить на нормализованную таблицу или JSONB с проверяемой схемой.

## Следующие срезы

1. Перенести попытки тестов и расчёт результата в модуль `assessment`.
2. Перенести назначение курса и правила доступа в модуль `enrollment`.
3. Разделить `course-actions.ts` на прикладные сценарии и тонкие адаптеры.
4. Добавить идентификатор идемпотентности входным событиям и retry-политику для конфликтов транзакций.
5. После стабилизации модульных контрактов заменить SQLite на PostgreSQL для production-нагрузки.

## Последствия

Новый функционал обучения строится через события и сценарии, а не через прямые записи Prisma из UI/API. Старые части приложения можно переносить вертикальными срезами без большого одновременного переписывания.
