# ADR-012: сертификаты о прохождении курса

## Статус

Принято (2026-08-25).

## Контекст

Почтовый шаблон `certificate` с переменной `{{certificateUrl}}` уже засеян в
настройках платформы и редактируется в админке, но за ним нет ничего: нет модели,
нет генерации, нет страницы, никто не отправляет письмо. UI отчисления с курса уже
обещает ученику, что тот «может лишиться сертификата». То есть фича заявлена в
интерфейсе, но не существует.

Факт завершения курса сейчас — **производная величина**: он пересчитывается на
чтение из живого прогресса ([`getCourseProgress`](../../src/lib/course-progress.ts)).
Такой факт «отваливается назад» при смене `completionMode` (сброс `isRequired` у
элементов), при переименовании курса и при чистке попыток во время отчисления.
Юридически значимый документ на подвижной основе строить нельзя.

## Решение

Четыре решения, которые иначе будут переоткрываться на каждом ревью.

### 1. Сертификат — иммутабельный снимок, а не пересчёт на чтение

Заводится модель `Certificate` с полем `snapshotJson` — застывшим на момент выдачи
снимком (ФИО, название курса, дата, этапы, балл, бренд платформы). Страница
сертификата рендерится **только** из снапшота, без живых джойнов на `Course`/`User`.
Выданный документ не меняется при последующем редактировании курса. Считаем по
**живым** `CourseItem` (где `archivedAt IS NULL`), а не по `publishedSnapshotJson`
курса: снапшот публикации может отставать от того, что ученик реально проходил.

### 2. Носитель — HTML-страница с print-стилями, не файл

Сертификат — серверная страница `/certificates/[serial]` с `@media print`, а не
PDF в хранилище. Причина — прод-образ: Chromium/Playwright там нет, из LibreOffice
стоит только `libreoffice-impress` (фильтр `writer_web_pdf_Export` для HTML
недоступен), PDF-библиотек в зависимостях нет. Существующий шаблон письма несёт
именно ссылку (`{{certificateUrl}}`), а не вложение — страница закрывает его без
единой новой зависимости. PDF-файл вынесен во вторую очередь (см. ниже) и
начинается только после эксперимента `soffice --convert-to pdf` в контейнере.

### 3. Выдача — отдельный модуль `certification`

Выдача триггерится из **трёх** мест в разных модулях: завершение материала
(`learning`), сдача теста и ручная проверка преподавателем (`assessment`).
Разместить логику внутри `learning` нельзя — тогда `assessment` импортировал бы
`learning` в обход правила зависимостей ADR-001. Поэтому — новый модуль
`src/modules/certification/` со слоями domain / application / infrastructure.

Хук выдачи вызывается **после** возврата из транзакции бизнес-операции и обёрнут в
try/catch: провал выдачи сертификата не должен ронять сохранение прогресса ученика
или проверку преподавателя. Атомарность нужна не между «просмотр страницы» и
«сертификат», а между «сертификат» и его `OutboxEvent` — и она обеспечена внутри
use-case (см. решение 4). Протаскивать `Prisma.TransactionClient` через границу
модулей ради общей транзакции запрещено (ADR-001).

### 4. Письмо — только через новый outbox-топик

Use-case открывает **свою** транзакцию, в которой атомарно пишет `Certificate` и
`OutboxEvent` с топиком `certification.certificate-issued-email.v1` — ровно то,
чего требует ADR-005. Прямой вызов `enqueue*` из server action запрещён; письмо
разгребает `email-worker`. `certificateUrl` в payload — уже **абсолютный**
(`${baseUrl}/certificates/${serial}`), потому что воркер про базовый URL не знает.

## Идемпотентность

Ключ идемпотентности — `@@unique([courseId, userId])`. Все три точки входа
безопасны при повторном вызове: use-case сначала ищет существующий сертификат и
возвращает `ALREADY_ISSUED` без записи, а гонку двух параллельных выдач (например,
одновременная сдача теста и learning-событие) ловит перехватом `P2002` на
уникальном индексе — тоже `ALREADY_ISSUED`, а не исключение.

## Правило выдачи

Сверх `progress.isCompleted` действуют три правила
([`decideCertificateIssuance`](../../src/modules/certification/domain/certificate-eligibility.ts)):

- **`requiredTotal > 0`** — курс без обязательных этапов никогда не «завершается»,
  и молчаливый отказ превратился бы в «сертификат не выдаётся и никто не знает
  почему».
- **пользователь должен быть назначенным учеником** — иначе менеджер, листающий
  курс в режиме превью, получил бы сертификат.
- **обязательные тесты считаются пройденными только при `isPassed`, а не
  `isResolved`.** По умолчанию `Course.quizGateMode = "RESOLVED"`, и `isResolved`
  включает `FAILED` — без этого правила сертификат ушёл бы ученику, ПРОВАЛИВШЕМУ все
  тесты. Реализовано отдельным вызовом `getCourseProgress({..., quizGateMode:
  "PASSED"})`. Это продуктовое решение; смена — правка одной строки.

`serial` — `randomBytes(16).toString("hex")`, а не `cuid`: cuid частично
предсказуем, а serial попадает в публичный URL. Статусы — строки (`ISSUED` |
`REVOKED`), как `Course.status` и `QuizAttempt.outcome`; enum'ов в схеме нет.

## Миграция: `db push`, не `migrate deploy`

Модель добавляется миграцией в `prisma/migrations/`, но `Dockerfile` **не
трогаем** — там остаётся `prisma db push` (ADR-010: прод-база накатана через
`db push` и не имеет таблицы `_prisma_migrations`, `migrate deploy` упал бы с
`P3005`; возврат `migrate deploy` блокирует `scripts/deploy-guard.mjs`).
После правки схемы миграция обязана совпадать с ней —
`npx prisma migrate diff --from-migrations prisma/migrations
--to-schema-datamodel prisma/schema.prisma --exit-code` должно вернуть 0 (тот же
шаг гоняет CI).

## Последствия

- Появляется первое во всём `src/` место создания `OutboxEvent` вне модуля
  `enrollment`; второе выглядит так же (общая транзакция сертификата и события).
- Отчисление с курса с удалением прогресса чистит попытки — сертификат при этом
  выживает целым, потому что его содержимое лежит в `snapshotJson` и не ссылается
  на `QuizAttempt`. Аннулирование при отчислении — опциональное, отдельным
  действием.
- Ретроспективная выдача уже завершившим курс, публичная верификация по QR и
  PDF-файл — отдельные очереди; в ADR будут дописаны при реализации.
