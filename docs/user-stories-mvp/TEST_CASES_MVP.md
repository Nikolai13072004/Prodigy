# MVP Test Cases

Источник: текущий срез `docs/user-stories-mvp`.

Документ собирает ручные тест-кейсы для приёмки и регрессии по текущему `MVP`. Набор можно использовать как чек-лист перед релизом, после крупных изменений и при ручной валидации окружения.

## Общие предусловия

- Развёрнуто тестовое окружение приложения.
- Подготовлены учётные записи ролей: `Администратор`, `Разработчик курсов`, `HR`, `Ученик`.
- В системе есть хотя бы один опубликованный курс, один черновик и один архивный курс.
- Есть тестовые пользователи в статусах `активен`, `ожидает подтверждения`, `заблокирован`, `архивирован`.
- Настроен тестовый почтовый ящик для проверки приглашений и уведомлений.

## Администратор системы

### TC-MVP-A-01 — Список пользователей и фильтры
- Story: `US-A-01`
- Тип: `Smoke`
- Предусловия: администратор авторизован, в системе есть пользователи с разными ролями и статусами.
- Шаги:
  1. Открыть раздел пользователей.
  2. Применить фильтры по роли, статусу и диапазону дат.
  3. Выполнить поиск по имени или email и изменить сортировку списка.
- Ожидаемый результат:
  1. В списке отображаются только подходящие пользователи.
  2. Поиск и сортировка работают без потери фильтров.
  3. Карточки и строки содержат актуальные статус и дату регистрации.

  1. Создать пользователя вручную, назначить роль и отправить приглашение.
  2. Открыть импорт пользователей и загрузить валидный CSV.
  3. Загрузить CSV с ошибками в данных и просмотреть отчёт.
- Ожидаемый результат:

  1. Черновик сохраняется и восстанавливается после обновления страницы.
  2. Публикация блокируется до выполнения обязательных условий.

  3. После повторной публикации ученик видит обновлённый контент.
