# US-C-12: Редактировать опубликованный курс без потери прогресса учеников

## Цель story
Разработчик курсов должен уметь редактировать опубликованный курс без потери прогресса учеников, чтобы обновлять материал.

Эпик: `Контроль версий и экспорт`.
Контур: `MVP`.
Приоритет: `Высокий`.
Текущий статус: `Ожидание`.

## Шаги реализации
1. При редактировании опубликованного курса — создается новая версия (черновик).
   Статус: ожидание.
   Контур: MVP.
   Что включено: При редактировании опубликованного курса — создается новая версия (черновик).

2. Ученики продолжают видеть старую версию до публикации обновлений.
   Статус: ожидание.
   Контур: MVP.
   Что включено: Ученики продолжают видеть старую версию до публикации обновлений.

3. После публикации обновленной версии — ученикам предлагается обновиться (или принудительно для новых учеников).
   Статус: ожидание.
   Контур: Развитие 1 очереди.
   Что включено: После публикации обновленной версии — ученикам предлагается обновиться (или принудительно для новых учеников).

4. Журнал изменений для администратора.
   Статус: ожидание.
   Контур: Развитие 2 очереди.
   Что включено: Журнал изменений для администратора.

## Что считать готовностью story
- При редактировании опубликованного курса — создается новая версия (черновик).
- Ученики продолжают видеть старую версию до публикации обновлений.

## Возможные следующие улучшения, но не блокеры для story
- После публикации обновленной версии — ученикам предлагается обновиться (или принудительно для новых учеников). Контур: `Развитие 1 очереди`.
- Журнал изменений для администратора. Контур: `Развитие 2 очереди`.
