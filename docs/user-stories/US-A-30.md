# US-A-30: Экспортировать данные платформы (пользователи, курсы, прогресс, сертификаты) в структурированном формате для бэкапа или передачи в другую систему

## Цель story
Администратор должен уметь экспортировать данные платформы (пользователи, курсы, прогресс, сертификаты) в структурированном формате для бэкапа или передачи в другую систему, чтобы решать рабочую задачу без лишних ручных действий.

Эпик: `Импорт/экспорт и миграции`.
Контур: `Развитие 1 очереди`.
Приоритет: `Средний`.
Текущий статус: `Ожидание`.

## Шаги реализации
1. Раздел «Экспорт»: выбор сущностей (пользователи, курсы, записи, прогресс).
   Статус: ожидание.
   Контур: Развитие 1 очереди.
   Что включено: Раздел «Экспорт»: выбор сущностей (пользователи, курсы, записи, прогресс).

2. Формат: CSV, JSON, XML.
   Статус: ожидание.
   Контур: Развитие 1 очереди.
   Что включено: Формат: CSV, JSON, XML.

3. Асинхронный экспорт с уведомлением по email, когда файл готов.
   Статус: ожидание.
   Контур: Не использовать.
   Что включено: Асинхронный экспорт с уведомлением по email, когда файл готов.

4. Защита паролем для экспортируемого ZIP-архива (опционально).
   Статус: ожидание.
   Контур: Не использовать.
   Что включено: Защита паролем для экспортируемого ZIP-архива (опционально).

## Что считать готовностью story
- Раздел «Экспорт»: выбор сущностей (пользователи, курсы, записи, прогресс).
- Формат: CSV, JSON, XML.

## Возможные следующие улучшения, но не блокеры для story
- Асинхронный экспорт с уведомлением по email, когда файл готов. Контур: `Не использовать`.
- Защита паролем для экспортируемого ZIP-архива (опционально). Контур: `Не использовать`.
