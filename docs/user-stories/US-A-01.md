# US-A-01: Просматривать список всех пользователей с фильтрацией по роли, статусу (активен/заблокирован), дате регистрации

## Цель story
Администратор должен уметь просматривать список всех пользователей с фильтрацией по роли, статусу (активен/заблокирован), дате регистрации, чтобы быстро находить нужных пользователей.

Эпик: `Управление пользователями и ролями`.
Контур: `MVP`.
Приоритет: `Высокий`.
Текущий статус: `Ожидание`.

## Шаги реализации
1. Таблица пользователей с колонками: ID, имя, email, роль, статус, дата регистрации, последний вход.
   Статус: ожидание.
   Контур: MVP.
   Что включено: Таблица пользователей с колонками: ID, имя, email, роль, статус, дата регистрации, последний вход.

2. Фильтры: по роли (админ, HR, разработчик, ученик), по статусу (активен, заблокирован, ожидает подтверждения), по диапазону дат.
   Статус: ожидание.
   Контур: MVP.
   Что включено: Фильтры: по роли (админ, HR, разработчик, ученик), по статусу (активен, заблокирован, ожидает подтверждения), по диапазону дат.

3. Поиск по имени, email, ID.
   Статус: ожидание.
   Контур: MVP.
   Что включено: Поиск по имени, email, ID.

4. Пагинация и сортировка по любому столбцу.
   Статус: ожидание.
   Контур: MVP.
   Что включено: Пагинация и сортировка по любому столбцу.

## Что считать готовностью story
- Таблица пользователей с колонками: ID, имя, email, роль, статус, дата регистрации, последний вход.
- Фильтры: по роли (админ, HR, разработчик, ученик), по статусу (активен, заблокирован, ожидает подтверждения), по диапазону дат.
- Поиск по имени, email, ID.
- Пагинация и сортировка по любому столбцу.
