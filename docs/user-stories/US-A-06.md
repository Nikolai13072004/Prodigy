# US-A-06: Видеть аудит-лог действий пользователей (кто, когда, что сделал, с какого IP)

## Цель story
Администратор должен уметь видеть аудит-лог действий пользователей (кто, когда, что сделал, с какого IP), чтобы расследовать инциденты и проверять безопасность.

Эпик: `Управление пользователями и ролями`.
Контур: `Развитие 1 очереди`.
Приоритет: `Высокий`.
Текущий статус: `Ожидание`.

## Шаги реализации
1. Лог с колонками: дата/время, пользователь (ID, имя), действие (users:update, courses:delete и т.д.), объект (например, user_id=123), IP-адрес, user-agent.
   Статус: ожидание.
   Контур: Развитие 1 очереди.
   Что включено: Лог с колонками: дата/время, пользователь (ID, имя), действие (users:update, courses:delete и т.д.), объект (например, user_id=123), IP-адрес, user-agent.

2. Фильтры по пользователю, типу действия, диапазону дат.
   Статус: ожидание.
   Контур: Не использовать.
   Что включено: Фильтры по пользователю, типу действия, диапазону дат.

3. Экспорт логов в CSV/JSON.
   Статус: ожидание.
   Контур: Не использовать.
   Что включено: Экспорт логов в CSV/JSON.

4. Хранение логов минимум 90 дней, настройка периода хранения.
   Статус: ожидание.
   Контур: Не использовать.
   Что включено: Хранение логов минимум 90 дней, настройка периода хранения.

## Что считать готовностью story
- Лог с колонками: дата/время, пользователь (ID, имя), действие (users:update, courses:delete и т.д.), объект (например, user_id=123), IP-адрес, user-agent.

- Фильтры по пользователю, типу действия, диапазону дат. Контур: `Не использовать`.

- Хранение логов минимум 90 дней, настройка периода хранения. Контур: `Не использовать`.
